# Eyadati — Backend Phases & Tasks

# Project Goal

Eyadati is a Flutter PWA SaaS application for doctors and patients.

Core idea:

* patients browse doctors and book appointments
* doctors manage appointments and subscriptions
* Supabase handles backend infrastructure
* Flutter handles frontend/PWA

Backend-first approach:

* complete architecture
* database
* authentication
* security
* business logic
* optimization

UI will be added later.

---

# General Supabase Best Practices

## Database

* Use UUID everywhere.
* Never use text IDs.
* Enable RLS on every table.
* Keep one source of truth.
* Avoid duplicated data.
* Use foreign keys properly.
* Add indexes only for actual query paths.
* Keep tables normalized.
* Avoid unnecessary triggers.

---

## Authentication

* Use Supabase Auth only.
* Never create custom password systems.
* Store app data inside `profiles`.
* `profiles.id` references `auth.users(id)`.

---

## Security

* RLS must protect everything.
* Never trust frontend filtering.
* Public browsing should expose only active doctors.
* Doctors should only access their own data.
* Patients should only access their own data.

---

## Performance

* Select only needed columns.
* Avoid unnecessary realtime subscriptions.
* Use indexes carefully.
* Generate slots dynamically.
* Avoid storing generated slots.
* Use pagination later for scalability.

---

## Cost Effectiveness

* Avoid heavy Edge Functions early.
* Avoid unnecessary cron jobs.
* Avoid storing duplicated scheduling data.
* Avoid large image uploads initially.
* Keep realtime disabled until needed.
* Keep queries optimized.

---
